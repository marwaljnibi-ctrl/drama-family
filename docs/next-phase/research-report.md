## 4. فحص معرّفات الفهرس (2026-11-10)

الأداة: `scripts/validate-ids.mjs` (قراءة فقط، لا تعدّل `data/shows.json`).

- 398 مسلسلًا، 10,234 حلقة، 10,234 مفتاح `showId|epId` **فريد** بلا تكرار.
- كل `show.id` و`ep.id` بلا `| / \ ? #` أو مسافات، ومقدار أطول مفتاح 64 حرفًا.
- جميع الحلقات لها `url`.
- **لا خطأ مثبتًا في الفهرس، ولم يُغيَّر شيء.**
- ملاحظة للتصميم: 313 حالة يتكرر فيها `ep.n` داخل المسلسل نفسه (مواسم داخل مسلسل واحد، أو «الحلقة الأخيرة/الأولى» يُقرأ رقمها بلا ترتيب). هذه ليست أخطاء معرّفات لأن `ep.id` فريد، لكنها تعني: **اربط الملفات بـ `epId` وليس برقم الحلقة `n`**. (هذا ما يفعله مفتاح التقدم الحالي.)
- المعرّفات تأتي من slugs موقع المصدر، وقد تتغير إن غيّر المصدر الروابط. عند التنفيذ يُخزَّن مع كل ملف `epId` و`showId` و`epNum` و`title` لإمكان إعادة الربط يدويًا.

### قيد عملي على التنزيل المتقطع
استكمال التنزيل بـ Range يحتاج رابط ملف مباشرًا يقبل `Range`. مصادرنا الحالية لا تعطيه بشكل مشروع: Express خلف جدار موافقة الكوكيز، وروابط HLS موقّعة بمعاملات قصيرة العمر. لذا يبقى هذا المسار **نظريًا** ولا يُبنى الآن. المسار المثبت عندنا هو الاستيراد اليدوي من Files (القسم 1).

### قرارات
- مشغّل Dizi الحالي باقٍ؛ لا استبدال ولا مكتبات جديدة.
- لا تنفيذ كامل لنظام التنزيل الآن؛ يُحفظ الفرع `exp/files-import` ونتائجه كما هي.

### إصلاح رجوع الفيديو إلى الصفر (بكود Dizi الموجود)
- **السبب المحتمل:** الاستكمال ينتقل إلى الثانية المحفوظة في `loadedmetadata` فقط، بينما يحفظ المشغّل التقدم عند أي `timeupdate/pause/pagehide`. إن تجاهل المتصفح الانتقال الأول (يحدث أحيانًا في iOS قبل `canplay`) يبدأ الفيديو من 0 ثم يُكتب 0 فوق التقدم القديم.
- **الإصلاح:** حارس `armed` في `app.js`: لا حفظ قبل تطبيق الانتقال، وإعادة المحاولة عند `canplay`. الفرع `fix/resume-zero` (commit 0923962) — **غير مدموج في main**.
- **الاختبار (Chromium، محاكاة سلوك iOS بتجاهل أول كتابة لـ `currentTime`):** قبل الإصلاح الفيديو بدأ من 0 → **FAIL**؛ بعده بدأ من 30 → **PASS**. الحالة العادية PASS في الحالتين.
- **iPhone الحقيقي: PENDING.** السبب الفعلي على الجهاز لم يُؤكَّد، والمحاكاة تمثّل فرضية فقط.

### 9.2 رابط Cloud.Mail (مصدر Express)

الطريقة: نفس منطق `getMailruDownloadHref()` في YDMassDownLoad (طلب مجهول إلى `api/v2/dispatcher` ثم `weblink_get` + مسار الرابط). طلبات عادية بلا تزوير ترويسات.

| الاختبار | النتيجة | التفصيل |
|---|---|---|
| الحصول على رابط التنزيل المباشر (خارج المتصفح) | PASS | dispatcher 200؛ تحويل 301 إلى `*.datacloudmail.ru/public/get/<token>/no/City 72.mp4` |
| HTTP Range / 206 / Content-Range | PASS | `bytes 0-0/3781927829` (≈3.52 غ.ب)، منتصف ونهاية الملف 206 صحيح |
| بصمة موثوقة | PENDING | ترويسة `Etag` من 40 خانة؛ لا نعرف أنها SHA-1 للمحتوى (Mail.ru يستخدم بصمة خاصة) → لا نعتمدها |
| CORS من صفحة Dizi (متصفح حقيقي، أصل localhost) | **FAIL** | dispatcher وصفحة الرابط وخادم التنزيل: «No 'Access-Control-Allow-Origin' header». `no-cors` يعطي استجابة opaque غير قابلة للقراءة |
| تنزيل تدريجي إلى OPFS من Dizi دون Safari/Aloha | **FAIL** | يمنعه CORS: الصفحة لا تستطيع قراءة البايتات |
| الاستكمال بعد الانقطاع من Mail.ru | **FAIL / غير ممكن** | للسبب نفسه |

**العائق الفعلي:** Mail.ru لا يرسل `Access-Control-Allow-Origin`. هذا قرار من المصدر، والمتصفح يطبّقه.

**الوسيط:** لم يُنشأ. الوسيط هنا سيتجاوز سياسة CORS لمصدر لم يصرّح لنا بالقراءة عبر الأصول، والمحتوى ملك طرف ثالث. كذلك يمرّر ≈3.5 غ.ب للحلقة عبر Workers، وهذا غير مناسب للخطة المجانية ولشروطها. القرار لصاحب المشروع، ونوصي بعدم استخدامه.

### 9.3 مختبر OPFS (الفرع `exp/opfs-download`، غير مربوط بالتطبيق)

- الملفات: `lab/opfs-download/` (Worker يكتب بـ `createSyncAccessHandle`، وتنزيل متسلسل بقطع Range، ونقطة حفظ بعد كل قطعة مع `flush`).
- معاينة منفصلة: https://exp-opfs-download.dizi-preview.pages.dev/lab/opfs-download/ (لا تمسّ معاينة الاستكمال).
- شروط «مكتملة»: الحجم من `Content-Range`، و`written == total`، و`flush` ثم الحجم على القرص == total، ومرور على صناديق MP4 حتى نهاية الملف بالضبط (ftyp/moov/mdat)، وإغلاق الملف، ثم تقديم وترجيع فعلي (50% و97% ثم 10%). البصمة لا تُفحص لعدم وجود بصمة موثوقة من المصدر، ولأن WebCrypto لا يدعم الحساب التدريجي.
- القطعة غير المعتمدة عند الانقطاع تُحذف، والجزء المسجّل يبقى للاستكمال.

| اختبار (Chromium، مصدر من نفس الأصل) | 593 ك.ب | 2.6 م.ب |
|---|---|---|
| probe: 206 + الحجم | PASS | PASS |
| انقطاع عند 50%: يبقى جزئيًا وغير مكتمل | PASS | PASS |
| verify يرفض الملف الجزئي | PASS | PASS |
| استكمال بعد 50% → مكتمل ومطابق (SHA-256 للاختبار فقط) | PASS | PASS |
| انقطاع عند 99%: يبقى غير مكتمل | PASS | PASS |

## 11. Streaming Proxy لحل CORS (2026-11-10) — فحص الشروط قبل التنفيذ

موافقة صاحب المشروع: وسيط مشروط باحترام صلاحيات المصدر وشروط مزوّد الخدمة، مجاني بلا خصم تلقائي.

| المزوّد (مجاني) | ما تقوله الشروط الرسمية | الحكم |
|---|---|---|
| Cloudflare Workers/Pages | الفيديو والملفات الكبيرة «المستضافة خارج Cloudflare» تبقى مقيّدة على الـ CDN في الخطط غير Enterprise؛ يُطلب Stream/R2/خدمات مدفوعة. Workers غير مذكور صراحة كاستثناء. (service-specific terms، صفحة delivering-videos، مدونة updated-tos) | ❌ غير مسموح صراحة |
| Vercel Hobby | سياسة الاستخدام المقبول تمنع proxying وhosting media for hot-linking؛ 100 غ.ب/شهر | ❌ ممنوع |
| Deno Deploy | «Not acceptable»: Forward proxy، Media hosting for external sites | ❌ ممنوع |
| Netlify Free | يمنع «general-purpose file storage or distribution» و«media streaming unrelated to a site» والمحتوى المخالف لحقوق الملكية؛ 300 رصيد × 20 رصيد/غ.ب ≈ 15 غ.ب/شهر | ❌ ممنوع + سعة غير كافية |
| Render Free | نص السياسة لم يظهر عند الجلب؛ لا يمكن تأكيد السماح | ⚠️ غير مؤكد → لا يُستخدم |

**النتيجة:** لم نجد مزوّدًا مجانيًا يسمح صراحةً بتمرير فيديو طرف ثالث. لذلك **لم يُنشأ أي وسيط ولم تُنفَّذ التجربة المعزولة** التزامًا بشرط احترام شروط المزوّد.

**أثر الاستخدام العائلي (تقدير):** حلقة 3.5 غ.ب. فرد واحد يشاهد حلقة يوميًا ≈ 105 غ.ب/شهر. أربعة أفراد × 3 حلقات أسبوعيًا ≈ 180 غ.ب/شهر. هذا يتجاوز كل الحصص المجانية المعروضة (15–100 غ.ب) حتى لو سُمح بالاستخدام.

**ما هو جاهز تقنيًا (مثبت):** Mail.ru يدعم Range/206 (3,781,927,829 بايت)؛ مختبر OPFS 9/9 على iPhone Safari؛ رابط Mail.ru المباشر يبقى صالحًا ≥ 54 دقيقة. العائق الوحيد: مكان قانوني ومجاني لتشغيل الوسيط.

**بديل محتمل يحتاج قرارًا:** وسيط على جهاز المنزل (PC) بلا مزوّد خارجي. القيود: الجهاز يجب أن يعمل، وصفحة HTTPS لا تقرأ من عنوان http محلي (mixed content) فيلزم HTTPS محلي أو نفق (Tailscale مثلًا، تطبيق على كل جهاز). غير مُنفّذ.
