# Dizi Turkish Series Identity & Poster Resolver

المصدر الوحيد لتحديد هوية المسلسل واختيار بوستره العمودي. مجاني بالكامل: TMDB (مفتاح مجاني موجود كسر `TMDB_API_KEY`) + Wikidata + TVmaze، بلا AI وبلا حسابات جديدة.

## الملفات
| الملف | الدور |
|---|---|
| `scripts/lib/identity.mjs` | المحرك: أسماء عربية ولاتينية، مصادر، تسجيل بالأدلة، قرار، اختيار البوستر والخلفية |
| `scripts/lib/images.mjs` | قاعدة العمودي الدائمة، تقييم الجودة، البصمة البصرية |
| `scripts/poster-pick.mjs` | التشغيل داخل المزامنة (`upgradePosters`) + أوامر CLI |
| `data/identity-index.json` | **الفهرس الدائم**: هوية كل مسلسل (معرّفات، أسماء عربية/تركية، أدلة، ممثلون) + الأسماء العربية المُتعلَّمة |
| `data/poster-map.json` | قرار البوستر لكل مسلسل (المعتمد نهائي ولا يُستبدل) |
| `data/identity-overrides.json` | تصحيحات بشرية: `{"tmdb": 123}` قاطع دائمًا، أو `{"names": ["Turkish Name"]}` تلميح يتحقق منه المحرك بالأدلة |
| `data/tr-catalog.json` | فهرس المسلسلات التركية من TMDB (يُجدَّد كل 45 يومًا) لمطابقة الأسماء الملصوقة في الروابط |
| `data/identity-testset.json` | مجموعة الاختبار الدائمة (الـ24) |

## كيف يقرر
1. **مرشحون** من: عنوان المصدر العربي وكل مشتقاته (كامل/أول 3 كلمات/آخر 3)، اسم لاتيني من slug الرابط واسم ملف صورة المصدر (`Sen-anla-large.jpg`)، تلميحات الأسماء، بحث TMDB والفهرس التركي، أسماء Wikidata العربية البديلة، ثم **ممثلو صفحة المصدر** (يُبحث عنهم في TMDB وتتقاطع أعمالهم) إن لم يُحسم.
2. **أدلة** (لكل مرشح): تطابق عربي (TMDB/Wikidata)، ربط Wikidata↔TMDB↔IMDb، اسم لاتيني، ممثلون مشتركون، **بصمة بصرية** لبانر المصدر مقابل لقطات المسلسل الرسمية، سنة الإنتاج (لا يسبق رفع الموقع بأكثر من سنة)، وعدد الحلقات كعامل خفيف فقط (ليس شرطًا). غير التركي يُرفض.
3. **قبول** فقط عند: دليل قوي واحد على الأقل + نقاط ≥ 4 + هامش ≥ 1.5 عن ثاني مرشح. وإلا: غلاف مؤقت وإعادة محاولة بتباعد 1/3/7/14/30 يومًا. فشل الشبكة العابر يُعاد بعد 6 ساعات بلا زيادة التباعد.
4. **بوستر**: كل بوسترات المعرّف الصحيح فقط، بنسبة عمودية، ثم الجودة، ثم اللغة (بلا نص ← تركي ← عربي، لأن العربي قد يحمل عنوانًا مدبلجًا يخالف الموقع). لا صورة أفقية تدخل `img3` أبدًا.

## القواعد الدائمة
- المطابقة المعتمدة لا يعاد فحصها ولا تُستبدل، والتصحيح اليدوي (`tmdb`) يتفوق دائمًا ولا يُلغى تلقائيًا.
- الفهرس يتعلّم الأسماء العربية المؤكدة ويستعملها للمسلسلات اللاحقة.
- لا يمسّ المفضلة ولا تقدم المشاهدة ولا أي بيانات مستخدم.

## الأوامر
```bash
node scripts/poster-pick.mjs --resolve [--ids a,b] [--all]   # معالجة غير المعتمد وطباعة الأدلة
node scripts/poster-pick.mjs --testset                       # إعادة حل الـ24 من الصفر ومقارنتها بالمتوقع (يفشل عند الاختلاف)
node scripts/poster-pick.mjs --audit --limit 40              # مقارنة المحرك بالمعتمد سابقًا (معايرة بلا كتابة)
node scripts/poster-pick.mjs --catalog                       # إعادة بناء الفهرس التركي
node scripts/poster-pick.mjs --apply data/shows.json         # تطبيق السجل على shows.json
```
اختبارات بلا شبكة: `node --test scripts/test-identity.mjs scripts/test-posters.mjs`.

## مسلسل لم يُحسم؟
أضف في `data/identity-overrides.json` اسمه التركي كتلميح: `"show-id": {"names": ["Turkish Name"]}` فيتحقق المحرك منه بالسنة والحلقات والممثلين والصورة. أو معرّف TMDB قاطع إن كنت متأكدًا: `{"tmdb": 12345}`.

## قاعدة الصور النهائية: بوستر عمودي 2:3 فقط
- كل صورة مسلسل في أي واجهة (Hero، التفاصيل، القوائم، الحلقات الجديدة، اكتشف، المفضلة، آخر المشاهدات) هي `img3` عمودي داخل إطار 2:3. لا صور أفقية ولا بانرات ولا خلفيات ضبابية ولا قص عشوائي ولا تمديد. من لا بوستر عموديًا له يظهر غلاف بعنوانه.
- نظام الأتمتة لا يجلب خلفيات أفقية ولا يكتب `img4`، و`--apply` يحذف أي `img4`. اختيار البوستر يقدّم 2:3 الحقيقي (0.62–0.72) على أي نسبة عمودية أخرى.
- `node scripts/poster-pick.mjs --reratio` يستبدل بوسترًا عموديًا غير 2:3 ببوستر 2:3 حقيقي لنفس المعرّف المؤكَّد، فقط إن لم تنقص جودته، ولا يمس المطابقات اليدوية.
- الاختبارات: `scripts/test-portrait-only.mjs` (ثابت + بيانات + حي على 4 مقاسات iPhone لكل الصفحات) و`scripts/test-identity.mjs`. تفشل CI إن عادت أي صورة أفقية.
